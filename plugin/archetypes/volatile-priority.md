# Volatile-priority

**Funny alias**: "Actually, forget what I said last week"

## Observable signals
- Changes direction mid-sprint without acknowledging the shift
- Introduces new priorities that override previous agreements
- Asks why something wasn't done differently, having previously requested the current approach
- Responds to progress updates by reprioritizing what's next
- Uses phrases like "actually, I was thinking...", "I talked to someone and now I think...", "can we pivot?"
- Doesn't always connect new requests to existing work in flight
- Good intentions, short memory for prior commitments

## Underlying need
Responsiveness and alignment with whatever is top of mind for them right now — often driven by external pressure they haven't fully communicated.

## Communication strategy
- Detail level: **medium** — document what was previously aligned on, then show current status vs. that baseline
- Update frequency: **weekly, with explicit alignment check at the end**
- Format preference: "current priority alignment" section first; show what was agreed, what changed, and what you're doing about it
- Tone: neutral, matter-of-fact, no passive aggression about the direction change

## Avoid
- Assuming last week's priorities still apply without confirming
- Showing frustration at direction changes (even implicitly)
- Delivering work without checking alignment first
- Long explanations of sunk cost
- "But you said..." — pointless and counterproductive

## Best output format
`useless-report:generate-volatile-priority-update`

Report sections: Current priority alignment → Work completed → Adjustments made to follow direction changes → Open questions for alignment → Upcoming work (pending confirmation)

## Example trigger messages
- "Actually, I think we should focus on X instead."
- "Wait, I thought we were doing Y — what happened to that?"
- "Can we pause this and switch to Z? It's more urgent now."
- "I talked to the client and they want something different."
- "Forget what I said last week — new direction."
